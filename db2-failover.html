Failover Procedures

Before any takeover — confirm HADR_STATE and log gap with MON_GET_HADR. Document the reason for takeover.

Graceful Takeover (Planned Maintenance)

Use when primary is reachable and standby is in PEER state. No data loss.

SELECT HADR_STATE, STANDBY_LOG_GAP FROM TABLE(MON_GET_HADR(NULL)) AS T;
TAKEOVER HADR ON DATABASE <DBNAME>
SELECT HADR_ROLE, HADR_STATE FROM TABLE(MON_GET_HADR(NULL)) AS T;

Forced Takeover (Emergency — Primary Unreachable)

DATA LOSS POSSIBLE Data loss equal to the current log gap will occur. Isolate the old primary from the network before executing to prevent split-brain. 
-- Isolate old primary (fence from network first!)
TAKEOVER HADR ON DATABASE <DBNAME> BY FORCE

Re-integrate Old Primary as New Standby

db2stop force                                    -- on old primary
START HADR ON DATABASE <DBNAME> AS STANDBY      -- restart as standby
SELECT HADR_STATE, STANDBY_LOG_GAP FROM TABLE(MON_GET_HADR(NULL)) AS T;
-- Wait for REMOTE_CATCHUP -> PEER

Failover Decision Tree

SituationActionRisk
Planned maintenanceGraceful TAKEOVER HADRNone
Primary unreachable, standby PEERConfirm isolation, then TAKEOVER BY FORCEPossible log gap loss
Primary unreachable, standby DISCONNECTEDRestore standby from backup first, then catch upHigher data loss risk
Both nodes unreachableRestore from latest backup to new nodeData loss up to last backup
