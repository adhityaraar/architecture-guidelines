HA & DR Principles

Cross-product standards applicable to all IBM HA and DR deployments.

Core Principles

PrincipleDefinition
RedundancyNo single component in the critical path should be a single point of failure (SPoF).
Geographic isolationHA targets within a DC; DR targets require a physically separate site.
AutomationFailover for Tier 1/2 workloads must be fully automated — human detection is too slow.
ObservabilityEvery component must emit health metrics; alerts must fire before users notice.
Regular DR testingUntested DR is not DR. Test failover at minimum once per quarter.
Minimal blast radiusDesign so a failure affects only the smallest possible scope of users/services.

Cross-Cutting Security Standards

ControlRequirement
Replication traffic encryptionTLS 1.2 minimum (TLS 1.3 preferred) for all replication links crossing untrusted networks
Service bindingBind all services to specific IPs — never 0.0.0.0
CredentialsNo hardcoded passwords; use environment variables or IBM Key Protect / HashiCorp Vault
Least privilegeHA admin roles scoped to minimum required permissions; review quarterly
Audit loggingLog all failover, takeover, and administrative actions; retain ≥ 90 days
Container imagesSource from registry.redhat.io only; non-root execution mandatory
