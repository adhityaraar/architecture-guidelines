watsonx.data — HA & DR Guide

High availability and disaster recovery for IBM watsonx.data lakehouse.

IBM watsonx.data is a hybrid, open lakehouse platform built on Apache Iceberg. Its HA design spans the query engine layer (Presto / Spark), the metadata catalog layer (Iceberg + Hive Metastore), and the object storage layer (S3-compatible or IBM COS).

Goals & Targets

GoalTarget
Query engine RTO< 5 minutes (auto-restart)
Catalog RPONear-zero (replicated metastore)
Data RPOZero (immutable Iceberg snapshots in replicated COS)
Data availability99.999% (multi-AZ COS buckets)

Architecture Layers

LayerComponentHA Strategy
Query EnginePresto coordinator + workers; Spark engineAuto-restart on failure; stateless workers replaced automatically; coordinator is auto-recovered by platform operator
Metastore CatalogHive Metastore (HMS) or Iceberg REST catalogActive/passive HA backed by replicated database (Db2 HADR or PostgreSQL Patroni)
Object StorageIBM Cloud Object Storage / S3Multi-AZ replication; Iceberg snapshots provide point-in-time recovery; no RPO concern for committed data
Control Planewatsonx.data management consoleDeployed on HA Kubernetes cluster (OpenShift multi-node); etcd and API server HA built-in

Network Requirements

InterfaceRequirement
Engine ↔ COSHigh-throughput (≥ 10 GbE); dedicated if possible
Engine ↔ MetastoreLow-latency LAN; bind to specific IPs — not 0.0.0.0
TLSTLS 1.2+ on all interfaces; TLS 1.3 preferred for COS and API endpoints

Key HA Checks

  • Presto/Spark engines deployed with auto-restart policy in operator config
  • Hive Metastore backed by HA database (Db2 HADR SYNC or PostgreSQL Patroni)
  • COS buckets configured with multi-AZ replication enabled
  • Iceberg table maintenance jobs scheduled (expire snapshots, remove orphan files)
  • Control plane deployed on multi-node OpenShift with etcd quorum ≥ 3 nodes
  • Engine restart tested and RTO measured
  • Metastore failover tested end-to-end (query resumption after failover)
  • Monitoring alerts configured for engine health, metastore connectivity, COS availability
Iceberg Snapshot Safety Net Every write to an Iceberg table creates an immutable snapshot. Even if the latest snapshot is corrupted or accidentally overwritten, previous snapshots remain accessible and queryable — providing built-in point-in-time recovery without additional backup tooling.
