watsonx.data — HA & DR Guide

High availability and disaster recovery for IBM watsonx.data lakehouse.

IBM watsonx.data is a hybrid, open lakehouse platform built on Apache Iceberg. Its HA design spans the query engine layer (Presto / Spark), the metadata catalog layer (Iceberg + HMS), and the object storage layer (S3 / IBM COS).

Goals & Targets

GoalTarget
Query engine RTO< 5 minutes (auto-restart)
Catalog RPONear-zero (replicated metastore)
Data RPOZero (immutable Iceberg snapshots in replicated COS)
Data availability99.999% (multi-AZ COS buckets)

Architecture Layers

LayerComponentHA Strategy
Query EnginePresto coordinator + workers; SparkAuto-restart; stateless workers replaced automatically by platform operator
Metastore CatalogHive Metastore (HMS) or Iceberg REST catalogActive/passive HA backed by replicated database (Db2 HADR or PostgreSQL Patroni)
Object StorageIBM COS / S3Multi-AZ replication; Iceberg snapshots provide point-in-time recovery
Control Planewatsonx.data management consoleDeployed on HA OpenShift cluster; etcd and API server HA built-in

Key HA Checks

  • Presto/Spark engines deployed with auto-restart policy
  • Hive Metastore backed by HA database (Db2 HADR SYNC or PostgreSQL Patroni)
  • COS buckets configured with multi-AZ replication enabled
  • Iceberg table maintenance jobs scheduled (expire snapshots, remove orphan files)
  • Control plane deployed on multi-node OpenShift with etcd quorum ≥ 3 nodes
  • Engine restart tested and RTO measured
  • Metastore failover tested end-to-end
  • Monitoring alerts configured for engine health, metastore, COS availability
Iceberg Snapshot Safety Net Every write to an Iceberg table creates an immutable snapshot. Previous snapshots remain accessible for point-in-time recovery without additional backup tooling.
