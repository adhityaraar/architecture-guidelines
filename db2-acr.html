Automatic Client Reroute (ACR)

Redirect application connections automatically after a HADR takeover.

ACR allows the Db2 client driver to reconnect to the new primary after takeover without application changes. It relies on the alternate server registered in the database directory.

Configure Alternate Server

-- Run on each client node (not on the database servers)
UPDATE ALTERNATE SERVER FOR DATABASE <DBNAME>
  USING HOSTNAME <standby_hostname> PORT <port>

-- Verify
LIST DATABASE DIRECTORY

ACR Behaviour by Client State

Client State at FailoverACR Behaviour
Idle connection (no active transaction)Automatically retried to alternate server — transparent to application
Active transaction in progressTransaction rolled back; connection retried to new primary — application must handle SQL error and retry
No ACR configuredSQL30081N — manual reconnect required by application
ACR ≠ Zero-Downtime ACR eliminates manual reconnection but active transactions are still rolled back. Design applications to retry on connection failure.

JDBC / .NET Connection Strings

// JDBC — clientRerouteAlternateServerName / Port
jdbc:db2://<primary_host>:50000/<DBNAME>:
  clientRerouteAlternateServerName=<standby_host>;
  clientRerouteAlternatePortNumber=50000;
  enableClientAffinitiesList=0;
