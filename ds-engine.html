Parallel Engine Resilience

Failure ScenarioBehaviourAction Required
Worker node crash during jobConductor detects lost worker; job aborted with error codeRe-trigger job from last checkpoint (if configured)
Worker node removed (planned)In-flight partitions drained; node removed from poolReduce partition count or add replacement before removal
Active conductor crashCluster manager promotes standby conductor; in-flight jobs abortedRestart jobs; investigate conductor logs
Shared filesystem unavailableAll jobs fail; conductor cannot load executablesRestore HA filesystem; no data lost if NFS/GPFS is HA-backed
Repository DB unavailableJob scheduling and Designer blocked; running jobs unaffected until completionTrigger DB failover; DataStage services reconnect automatically

Checkpointing Best Practice

For long-running jobs, enable restart capability using sequential file stages with restart markers, or partition-level checkpoints in the job design. This limits re-work to the last checkpoint rather than a full restart.

Design Jobs for Restartability Always design DataStage jobs to tolerate a restart from a known-good point. Use surrogate key lookup stages idempotently, and mark intermediate files as persistent so they survive a conductor failover.
