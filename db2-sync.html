Synchronisation Modes

Choose the right sync mode based on RPO requirements and network latency.

ModeCommit AcknowledgementRPOPerf ImpactUse When
SYNCLog flushed to standby diskZeroHigh (RTT)Tier 1 — zero data loss mandatory
NEARSYNCLog received by standby~1 pageMediumLow-latency LAN, sub-second RPO acceptable
ASYNCLog on primary disk onlySeconds–minMinimalWAN DR replication
SUPERASYNCImmediate (no standby ack)UnboundedNoneMonitoring replicas only — NOT for production HA
SYNC over WAN SYNC adds one round trip per commit. For sites > 5 ms RTT apart, use NEARSYNC or ASYNC. Reserve SYNC for same-DC, dedicated low-latency links.

Changing Sync Mode (no restart required)

UPDATE DB CFG FOR <DBNAME> USING HADR_SYNCMODE NEARSYNC
-- Change takes effect immediately; verify with MON_GET_HADR

Peer Window

The HADR_PEER_WINDOW parameter defines how long the primary waits for the standby to acknowledge logs before downgrading to ASYNC mode.

UPDATE DB CFG FOR <DBNAME> USING HADR_PEER_WINDOW 120  -- seconds
-- A value of 0 disables the peer window (not recommended for Tier 1)
